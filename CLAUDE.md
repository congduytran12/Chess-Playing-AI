# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Pygame chess game with a NegaMax/alpha-beta AI, local hotseat, and online multiplayer. It runs natively on desktop and in the browser via pygbag (Python compiled to WebAssembly), deployed on Vercel.

## Commands

Run the desktop game. It must be run from inside `game/`, because assets load by relative path (`sounds/...`, `images/...`) and modules import each other as top-level modules (`from engine import ...`), not as a package:

```bash
cd game
pip install -r requirements.txt   # pygame==2.1.2, pygbag
python main.py
```

Build the web (WASM) bundle. This is what Vercel runs. The output goes to `game/build/web`:

```bash
npm run build
```

The build pins pygbag 0.9.3. It also downloads stockfish.js 17.1.0 (the lite single-threaded build, its `.wasm` and its GPL license) from unpkg into `game/build/web/stockfish/` (jsDelivr refuses the package: it is over 150 MB), and the pygbag runtime JS files locally and uses `sed` to rewrite `index.html` so the page loads them from the local copies instead of the CDN. Keep those versions in sync if you change one.

Run the tests from the repository root (standard library `unittest`, no extra packages; the account API tests need `flask` and `requests`, and the UI tests need `pygame`):

```bash
python -m unittest discover -s tests
```

They cover move generation (perft counts), the AI search, the Stockfish bridge (against a stand-in UCI engine; `tests/support.py` sets `CHESS_NO_STOCKFISH=1`, so every other test plays `chessAi`'s moves whether or not Stockfish is installed), PGN, network message handling, the hint and settings storage, the account API against an in-memory Supabase stand-in, and the game loop itself, run headless with scripted clicks. There is no linter configured.

## Architecture

- `game/engine.py`: rules engine. `GameState` holds an 8×8 board of two-character strings (`'wK'`, `'bp'`, `'--'` for empty). It handles move generation with pin/check detection (`checkForPinsAndChecks`), castling rights, en passant, and draw detection (50-move rule, insufficient material, position keys for threefold repetition). `Move` stores a move, including its `promotionChoice`. Game moves go through `makeMoveWithSan`, which records standard algebraic notation in `move.san`; `findMoveBySan` parses it back. The AI search calls plain `makeMove`. Every state change in `makeMove` must be reversed in `undoMove`, because the AI search depends on make/undo.
- `game/stockfish.py`: Stockfish, which plays the computer's moves, finds the hints and analyzes finished games. The `engine` singleton (`Engine`) speaks UCI to stockfish.js in a Web Worker in the browser (`WORKER_URL`, JS helpers through `js.eval`, polled) or, on desktop, to a native executable (`findExecutable()`: `STOCKFISH_PATH`, `stockfish` on PATH, or the repository's `engines/` folder, which git ignores) read by a thread. `main()` calls `engine.start()` once; the handshake runs in the background (`state`: 'off', 'starting', 'ready', 'failed'). Positions go as `position startpos moves ...` from `Move.getCode`, so Stockfish sees repetitions. `findBestMove(gs, validMoves, level)` (held to `LEVEL_ELO[level]` with `UCI_LimitStrength`, for `chessAi.LEVELS[level]`'s time), `searchPosition(gs, validMoves, seconds)` (full strength; hints and the analysis) and `evaluate(gs, seconds)` (the draw-offer decision; None while busy) have `chessAi`'s shapes and fall back to `chessAi` when Stockfish isn't ready within `READY_WAIT` or fails. One search runs at a time (a lock); a cancelled search is stopped, and the next one reads its `bestmove` before starting.
- `game/chessAi.py`: the game's own AI, used when Stockfish isn't there.
  - **Search:** `searchPosition()` runs NegaMax with alpha-beta pruning by iterative deepening until a time budget runs out, then returns the best move of the last finished depth. It adds quiescence search over captures and promotions, check extensions, a transposition table keyed by `GameState.getPositionKey()`, killer and history move ordering, null move pruning (`makeNullMove` passes the turn, and must be undone even on a timeout), late move reductions, and repetition detection against the game's position history. A depth cut off by the clock still contributes the best move it found so far.
  - **Levels:** `findBestMove()` plays from the opening book (`BOOK_LINES`, built on first use) while it can. After that it searches with the settings in `LEVELS[LEVEL]`: time, depth cap, and root noise that makes the lower levels beatable. `main.py` sets `chessAi.LEVEL` from the difficulty dropdown.
  - **Responsiveness:** the search raises `SearchTimeout` when time runs out, and the caller undoes back to the root. It yields to the browser every `YIELD_SECONDS`.
  - **Evaluation:** `scoreBoard()` counts material plus piece-square tables, with a king table that switches for the endgame. It returns a score in pawns, positive when White is better.
- `game/main.py`: Pygame UI and the game loop (`async def main()`), covering rendering, the move log, the promotion popup, the mode toggle (vs AI / local 2-player / online), clocks, hints, resign and draw offers, review and analysis after the game, and online sync (see below). `panelRows()` names the side panel's controls row by row, `panelLayout()` turns them into rects, and both click handling and drawing use it. The bottom row is always Undo, Restart, Account and the menu (a narrow three-line icon button, `CONTROL_WEIGHTS`); the menu's items are `MENU_ITEMS` (Save/Load PGN, Flip board, Settings, How to play), laid out by `menuItemRects()` upwards from its button, drawn last like dropdown options by `drawMenu()`, and run by the nested `menuAction(name)`. Online without a room there is no game: the Resign/Offer Draw row is left out, Undo is disabled and the board doesn't take moves. Online in a room, a row under the room's line holds Copy link (host only), Chat and Hint (hints work online too, on the player's turn, from the same daily count): `panelRows`/`panelLayout` take a 6th argument `guest` (the guest's row is Chat and Hint), and every call in `main()` passes the frame's `guest`. The board's orientation `flip_board` is worked out every frame (Black at the bottom for the online guest and when playing Black against the computer) and then turned around when `boardFlipped` is set (F or the menu; `resetGame` clears it); everything that draws or clicks the board takes that `flip_board`. Nested helpers inside `main()` own the shared state changes: `resetGame`, `playMove` (every move of the game goes through it), and `takeBack`. All three call `clearReview()`, which leaves the review (or looking back) and cancels the analysis. `reviewTo(ply)` replays the moves onto `reviewGs` for display, during the game too (looking back: arrow keys, Home/End, a click on a move in the log, or on the evaluation graph after the game). While looking back in a live game, `drawLookBackBanner()` shows `lookBackText()` across the top of the board, a board click only returns (`reviewTo(len(gs.moveLog))`), the clocks keep running and the log highlights the shown move; any new move returns through `playMove`, and a game that ends meanwhile returns to show its result (`wasGameOver`). `analyzeGame()` runs as a background asyncio task on its own `GameState`, searching each position for `ANALYSIS_SECONDS`. `moveMarks()` turns the score drops into `??`/`?`/`?!` marks.
- `game/pgn.py`: PGN export and parsing, and saving and loading files. Desktop uses a tkinter file dialog and falls back to a `saved_games/` folder. In the browser, `js.eval` helpers trigger a download or a file picker, and the picked file's text is polled each frame.

### Online sync protocol

Online games sync whole game states, not single events, so lost messages and rejoins recover on their own:

- **State messages:** every change to the game (move, accepted undo, resignation, accepted draw, new game) bumps `onlineVersion` and sends a `state` message. It holds the game number, a random game id (`gid`, shared by both players and used to match their rating reports), the version, the full move list in coordinate notation (`Move.getCode`, e.g. `e2e4 e7e8n`), the time control, the clocks, and the result. Use `publishChange()` for local changes. Only a new game bumps `onlineGame` and resets the version to 0.
- **Receiving:** anyone with the room's code can post to it, so nothing received may stop the game: only states that pass `wellFormedState()` count, and the `player` field goes through `onlinePlayerInfo()` (a finite rating, a name of username characters). The newest state in a batch is compared by `(game, version)`. A newer state is adopted by `adoptState()`, which undoes back to the common moves and replays the rest. An older state means the sender is behind, so we send ours back, rate-limited by `SYNC_REPLY_MS`. Equal versions that disagree are settled in favour of the host.
- **Heartbeats:** the side waiting for the opponent (or both, after the game) re-sends its state every `HEARTBEAT_MS`, so a dropped message can't leave both players waiting.
- **Presence:** a player who has sent nothing for `PRESENCE_MS` sends a `ping`. `network.py` stamps every incoming message with ntfy's server time (`_time`) and keeps the room's latest in `net.server_time`; `presenceStatus()` compares the opponent's latest message with it, so the two players' clocks never matter and old messages replayed on joining don't count as presence.
- **Joining and rejoining:** connecting sends `sync_request` (with this connection's `join` id), and the ntfy backlog (`since=30m`) replays older states. Our own `sync_request` comes back after the backlog (or as its newest message), and its `_time` is kept as `joinedAt`: what came before it is the room's history. Once it is known, `caughtUp` is True. Without it after `JOIN_ECHO_MS`, `net.server_time` stands in.
- **Quick chat:** `chat` messages carry an index into `QUICK_CHAT` (`id`), never typed text. `incomingChat(msg, opponentRole, serverTime, joinedAt)` shows one only from the opponent's role, with a valid id, with `_time` within `CHAT_FRESH_SECONDS` of `net.server_time`, and not before we joined (none while `joinedAt` is None, none sent more than `CHAT_FRESH_SECONDS` before it), so chats replayed from the backlog on joining don't show, even when one is the backlog's newest message. They don't depend on `(game, version)`.
- **Requests and offers:** `undo_request`, `draw_offer`, `undo_declined` and `draw_declined` are transient. They only count when they come from the opponent's role about the current `(game, version)`, which also skips stale ones in the backlog.
- `api/account.py`: a Flask function at `/api/account` for player accounts (register, login, refresh, recover, set_password, me, save_game, games (the newest `GAMES_LISTED`), game, report_online, leaderboard). `recover` asks GoTrue for a reset email (`POST /auth/v1/recover`, `redirect_to` the site) and answers `{sent: true}` whatever the email (also for GoTrue's 429, which only a known address gets when asked again within a minute), 503 only when the service fails (5xx); `set_password` saves a new password with the reset link's access token (`PUT /auth/v1/user`; 401 means the link expired). Each request is a POST with an `action` field, and signed-in actions carry an access `token`. It talks to Supabase with `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (Vercel environment variables) using plain `requests`: GoTrue for auth and PostgREST for data.
  - **Schema:** in `supabase/schema.sql`. Row level security is on with no policies, so the tables are reachable only through this function.
  - **Ratings:** `report_online` counts an online result only when both players report the same result for the same game id. The SQL function `apply_rated_game` applies it once per game, and at most 3 rated games per pair of players in 24 hours.
- `game/account.py`: the client side, the `account` singleton.
  - **Requests:** non-blocking. In the browser they use `fetch` and are polled each frame; on desktop they run on an executor thread.
  - **Server:** the browser build calls its own site; desktop calls `https://chess-playing-ai.vercel.app` (override with `CHESS_API_URL`).
  - **Sign-in:** the refresh token is kept in `localStorage` or `~/.chess-playing-ai-account.json`.
  - **In `main.py`:** account work runs through `startRequest()`, and finished requests are handled once per frame. The account window is drawn by `drawAccountWindow()`, with `accountLayout(view, count, scroll)` as its layout; every view's box is fitted to its content (`count` is the list's rows, or the profile's rows of results from `accountRowCount()`, and the nested `accountRects()` gives the layout as drawn). Views: `ACCOUNT_FORMS` ('signin', 'register', 'forgot', 'newPassword'), 'profile' (rating and a won/drawn/lost bar per mode, `drawProfile()`, `drawRecordBar()`), 'games' and 'leaderboard'. The saved games scroll like the move list (`accountListLayout()`, `accountScroll`, `accountPress`, `accountThumb`, the shared `scrollbarRects()` / `firstRowForThumb()` / `drawScrollbar()`), and a game opens on button up. Messages go through `setAccountMessage(text, tone)` ('error' or 'success'). Forgot password: the sign-in form's link opens 'forgot' (`account.recover(email, browser.siteUrl())`); a page opened from the reset email (`resetLinkFromHash(browser.locationHash())`, type=recovery) opens 'newPassword', naming the account from the access token's email claim (`tokenEmail()`, shown only), which saves through `account.setPassword(token, password, refresh)` and signs in with the link's refresh token. The hash leaves the address bar at startup, for any email link that carries tokens (`hashHasSignIn()`) or an error: the tokens are kept in `resetLink`, so a reload doesn't reopen the form. A link's error text is never shown (anyone can make such an address): `otp_expired` and anything else get fixed messages. Once the password is saved, `setPassword` succeeds even if the sign-in after it fails (then it signs out, and the form says to sign in with the new password). The How to play window (`H` key or the menu) works the same way: `drawHelpWindow()` draws the page of `HELP_PAGES` in `helpPage`, placed by `helpPageLayout(page)` (the help-fit test checks every page against it); keep its text in step with the game's features. An item is (icon, heading, text) or (icon, heading, text, diagram): a diagram (`CHECK_DIAGRAM`, `PROMOTION_DIAGRAM`, `CASTLING_DIAGRAM`, `EN_PASSANT_DIAGRAM`: files, ranks, pieces, arrows, ghosts, rings, tints, check) is drawn by `drawMiniBoard()` at the item's right, in the board's colors and piece set (`DIAGRAM_IMAGES`), and the text wraps beside it. On the first visit (setting `seenHelp` False) How to play opens by itself, except after a password reset link (it waits for a later visit) and behind an invite link's Join prompt (it opens once that is answered); closing it in any way stores `seenHelp` True, and once it has been open in any way (H while the Join prompt waits, say) it doesn't open by itself again. The UI tests store `seenHelp` True in `setUpClass`. Finished games are saved automatically by `saveFinishedGame()`, which also reports online results. Online messages carry a `player` field (uid, name, rating) when the sender is signed in.

Server tests aren't in the repo. The account API was tested against an in-memory imitation of Supabase; anything touching the schema needs a real Supabase project to verify.

## Constraints

- **Browser compatibility:** everything in the game loop is async. Long-running work must `await asyncio.sleep(0)` regularly, as the main loop, animations, the promotion popup, and the AI search (at least every `YIELD_SECONDS`) already do. Without this, the browser tab freezes. Don't add blocking calls, threads, or synchronous network I/O on the WASM path.
- `asyncio.run(main())` at the bottom of `main.py` is the entry point that pygbag requires.
- Sound files are `.ogg` so they work in the browser. The short alert sounds (check, game-start, game-end, low-time, notify) are synthesized by `tools/make_sounds.py` (needs numpy and soundfile, which the game itself doesn't); rerun it to change them.
- `game/build/` is committed to git (Vercel rebuilds it). `__pycache__/` and `.pyc` files are ignored by `.gitignore`.
